## Investigated Fully, Not Fully Closable (documented in detail, not left vague)

**§3.5 — `is_seat_vacated()` — INVESTIGATED FULLY, NOT CLOSABLE IN P1 SCOPE.** Root cause confirmed: MOG2 absorbs stationary subjects into the background model, so "no motion" ≠ "no occupant." Two distinct symptoms found on real DAHISAR1 footage (same 39,600-frame window): (1) false-positive vacancy flags during genuine stillness — confirmed on both short (<1s) and unusually long periods, including a 922-continuous-second false vacancy at seat_2 while a person sat visibly present; ruled out as a wiring/indexing bug via direct `fused_tracks` probing at 5 timestamps across the full window (seat attribution logic itself works correctly — there is simply zero motion blob to attribute). (2) Fragmentation of continuous real absences into multiple disconnected shorter periods — one genuine 190+s departure (seat_4) surfaced as a single 95.59s fragment. No false negatives found — 2/2 real departures spot-checked were eventually detected, just fragmented in one case. Attempted a full fix: traced `p1_p2_tracker.py` and `detector.py` directly and confirmed person-tracking is 100% motion-gated end to end — no independent presence data exists anywhere in P1's scope to redefine "vacant" against. This is an architecture-level blocker requiring P2 + owner sign-off (periodic motion-gate bypass, or an independent presence signal), not a code defect fixable inside `heuristics.py`. Not deleted, not rewritten without that sign-off. See Remaining items #8 (coordination) and #9 (regression clip, planned for validating a future fix, not a substitute for the architecture decision).

**Plan 1.5 — Grid-based ROI (`get_grid_rois()`) — REAL PROGRESS MADE, NOT FULLY CLOSABLE YET.** Confirmed the original gap first: `get_rois()` (the previously-closed function) generates box *boundaries* via `cv2.findContours()` on the motion mask — grid-based seat *tagging* was already correct, but boundaries were never grid-based, meaning the plan's own stated rationale ("contours merge in crowded scenes") was never actually addressed. Built `get_grid_rois()` in `roi.py` (additive — `get_rois()` untouched, confirmed live-pipeline-safe): per-seat-cell intensity gate (`_seat_intensity()` reused verbatim from `baseline.py`; threshold reused by reference from `event_clustering.segment_events`'s own default via `inspect.signature`, not re-typed) → `cv2.findContours` used *only* as a shape-validity check on that cell's own crop (never a boundary source, reusing `is_valid_roi()`'s existing `MIN_CONTOUR_AREA`/`MIN_FILL_RATIO`/`MIN_ASPECT_RATIO`/`MAX_ASPECT_RATIO` thresholds verbatim) → emits the seat's own fixed cell rectangle as `bbox`. **Merge-fix and seat-loss-recovery proven with real evidence:** 8/8 unit tests pass (synthetic merge-fix proof, noise-rejection, boundary-uses-cell-not-contour, zero-motion-skip, plus 3 `crop_bbox` edge-clipping tests added in the follow-up round); real-clip run on Camera12 clip 4 (1,146 frames) found **140 frames where `get_grid_rois()` detected a seat that `get_rois()`'s emitted output missed entirely** — direct, real-footage evidence the "losing a seat to a merged/misattributed contour" failure is fixed.

Follow-up work quantified a **cross-seat contamination cost** of the fixed-cell-rectangle design: the full-cell `bbox` overlaps another seat's rectangle in 211–213% of emitted boxes (Camera12 clip 4 and DAHISAR1 clip 07, 39,600-frame window both measured) — confirmed via visual spot-check (4 frames, 2 per clip) to correspond to real intruding people in 3/4 cases, including a genuine three-way overlap zone (Camera12 frame 60: seat_60/seat_61/seat_64 simultaneously). Proposed and implemented a hybrid-crop mitigation (`crop_bbox` field: the validated contour's own bounding box, +9px margin reused from `DILATE_KERNEL_SIZE`, clamped to never exceed the cell's own rectangle) — real-clip re-measurement showed it **roughly halves but does not eliminate** the contamination (Camera12: 212.6%→114.0%; DAHISAR1: 211.0%→100.5%), explicitly falling short of the near-zero result needed to call it resolved. Root-caused the shortfall: pairs whose contamination came from cell-oversizing improved dramatically (DAHISAR1 seat_4↔seat_6: 45.2%→2.65%), but pairs where the *seat rectangles themselves* substantially overlap (Camera12 seat_61↔seat_66, DAHISAR1 seat_1↔seat_2/seat_4↔seat_5/seat_5↔seat_6 — the same perspective-occlusion root cause as the already-closed Bug 3) barely moved, since a real occupant's tightly-cropped body is still genuinely inside both cells' shared zone regardless of crop tightness. Frame-level recheck of three specific earlier examples: neighbor-intrusion resolved as expected (Frame 11), but the expected fragmentation case did not reproduce (Frame 6) — `get_grid_rois()`'s per-cell-scoped contour search turned out to behave differently than `get_rois()`'s whole-frame-contour-plus-post-hoc-tagging approach at that specific frame, reported honestly rather than forced to match the prediction.

**Explicitly not marked resolved, per the standing evidence bar.** Not wired into the live pipeline — `p1_p2_tracker.py` still calls `get_rois()` exclusively; the switch is a separate, explicit decision, deferred pending the contamination question. `crop_bbox` is not wired into `detect_objects()`/`PoseGestureAnalyzer` (out of scope until the switch decision). See Remaining item #1 for the two paths to actual closure.
